# 面试讲解与问答

## 两分钟讲解

我做的是一个本地日历记忆 Agent。用户可以在日历中管理任务，也可以把目标交给 Agent。后端的运行时会先读取相关记忆，让模型决定下一步，再通过服务端的 Skill 白名单和严格 Schema 调用工具，观察结果后继续决策。

这个循环有明确边界：普通聊天一次，简单能力两次，多步任务最多六次，还限制 Token、时间、重复调用和连续失败。Run 和事件存在 SQLite，浏览器断线不会取消任务。服务重启会把中断 Run 转为等待确认；已有成功写入通过幂等回执避免重复执行。

记忆分为 Run 内工作记忆、带有效期的短期记忆、五类长期记忆。长期记忆关联来源、版本和父子关系。模型产出 MemoryOperation，代码验证来源、版本、锁定和敏感内容；高风险变化再经过独立模型校验。用户纠正后旧证据退出检索，忘记会连同派生内容和缓存一起屏蔽。只有通过质量门的来源才进入七天恢复期。

检索用同一个 SQLite 中的 FTS5 和 sqlite-vec，本地多语言模型生成向量。日历数据库始终是日期、状态和清单的事实来源，记忆只补充语义背景。天气后台只创建建议，不能自动修改任务；永久删除根本不在模型工具表里。最后，我用隔离的合成数据比较无记忆、关键词记忆和混合检索，并保留模型失败的证据。

## 演示步骤

1. 在记忆中心保存常住城市，例如 Melbourne, Victoria；有临时行程时另外设置有效期。
2. 创建次日户外活动，进入 Agent 页请求检查天气。展开工具轨迹观察读取日历、查询天气和确定性阈值结果。
3. 有天气建议时回到首页，选择新日期并接受，查看新的前台修改 Run。实际天气可能没有触发阈值，不能把正常预报伪装成危险；自动化测试用固定合成预报演示触发分支。
4. 添加一条偏好，更新语义索引，用不同语言询问相关问题。纠正后再次询问，检查旧记忆已失效。
5. 展示来源、哈希、版本、访问记录，以及高风险校验失败时保留原文的回归测试。
6. 打开真实评测 JSON，区分聊天开销、巩固开销、未产生答案的失败和内容评分失败。

## 常见追问

**为什么不用 LangGraph？**

目标是展示最小可解释的运行时边界。这里自己实现了状态、预算、持久队列、工具协议和恢复策略；没有声称自研运行时比成熟框架更适合所有生产场景。

**为什么需要 SQLite 唯一索引，而不是只写 Prompt？**

Prompt 无法阻止两个并发请求同时写入。活动 Run 的部分唯一索引阻止同 Session 重叠写 Run，日历版本字段拒绝跨 Session 的旧状态覆盖。

**断线和进程崩溃有什么区别？**

断线只是 SSE 订阅结束，独立 worker 继续执行。进程崩溃无法断定外部模型调用是否成功，因此重启后先等待用户确认。已经提交的日历操作有回执，不能静默重复创建。

**工具执行一半失败怎么办？**

普通流程保留已成功的合理操作并报告失败。只有声明原子的 Skill 才触发补偿；补偿是服务端生成的有限逆操作，也校验版本，不会偷偷覆盖期间的用户修改。

**记忆纠正为什么会取消运行中的 Run？**

正在进行的请求可能已经装配了旧证据。这个单用户版本选择保守地终止相关可用上下文，要求新 Run 重新装配，避免“检索里删了，模型仍拿着旧 Prompt 行动”。

**向量库失败会怎样？**

检索保持关键词降级；两路都没有证据时返回空结果，不制造记忆。界面显示语义索引状态。索引按模型、版本和维度保存；后台构建期间旧 Provider 和旧索引继续服务，只有新索引覆盖当前记忆版本后才在事务中切换活动指针。

**天气为什么不让模型直接判断风险？**

降雨概率、温度和风速阈值属于用户配置，由代码比较。模型可以解释影响，但不能提高风险等级、改阈值或在后台改日期。

**程序性记忆是自动自我进化吗？**

不是。这里只有天气策略候选：收集多个成功 Run 的证据，执行合成阈值检查，再让用户决定是否启用。综合评测另用两个真实模型重复启用前后的天气任务，记录成功、误操作与成本；确定性阈值检查和模型回放的分数分开解释。

**如何解释评测分数？**

先说明样本量只有每组八题，包含中英文同义问法和干扰记忆。Recall 衡量是否找到目标来源，成功率检查答案中的关键事实，协议错误仍算失败。来源相关答案不等于全面正确，所以报告保留原始合成答案供复核；尚未覆盖的指标不能填成零或一。
